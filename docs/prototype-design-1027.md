# POSTIC 중간평가 프로토타입 설계

작성일: 2026-10-27 · 마감: **2026-10-27 (오늘)** · 담당: 노정운(CTO)

## 1. 목적

학교 중간 평가 시연용. 사업계획서의 "01 기술 검증" 단계를 실물로 보여준다.

> 태그(Tag ID) → 게이트 → DB → 앱. 매장에 걸린 옷이 자동 인식되고, 손님이 폰으로 그 옷을 보고 바로 결제·픽업까지 이어진다.

## 2. 성공 기준

1. 걸어둔 BP106 **전부** 인식된다. 직원 대시보드에 `N/N 온라인`이 표시된다.
2. 태그를 게이트 범위 밖으로 가져가면 **10초 안에** 목록에서 사라진다. 다시 가져오면 다시 뜬다. 이것으로 "실시간"을 증명한다.
3. 손님 흐름을 클릭으로 끝까지 진행할 수 있다: 인식된 상품 → 상세 → 사이즈 선택 → 피팅 요청 또는 구매 → **목 결제** → 픽업 번호.
4. 심사위원이 자기 폰으로 URL을 열어도 같은 화면이 보인다.

## 3. 범위

**안 하는 것**
- 배터리리스 인레이 (BP106 배터리 비콘으로 대체)
- 실제 PG 결제 (목 결제만)
- 정밀 위치 추정 (AoA, 삼각측량)
- 폰 BLE 직접 스캔
- 로그인과 회원
- POS·ERP 연동
- 다점포

**실패로 치는 것** (기능은 돌아가도 실패)
- 시연 중 태그 일부가 안 뜬다.
- 학교 인터넷이나 Wi-Fi 문제로 시연이 멈춘다.
- 가짜 데이터를 진짜처럼 보여준다. 시뮬레이터를 켜면 화면에 반드시 `시뮬레이션` 배지를 띄운다.

## 4. 하드웨어 구성

| 역할 (계획서) | 프로토타입 대체품 | 수량 |
|---|---|---|
| BLE Inlay | Feasycom FSC-BP106 (CR2025, BLE 5.1, iBeacon) | N개 (상품당 1개) |
| Smart Gate | Minew G1 (Wi-Fi 2.4GHz/Ethernet, HTTP/MQTT 업로드) | 1대 |
| 네트워크 | 폰 핫스팟 또는 휴대 공유기 (2.4GHz) | 1 |

### BP106 설정 (FeasyBeacon 앱, iOS/Android)
- **전원:** 가운데를 길게 누른다. LED가 3번 깜빡이면 켜진 것이다. 출고 시 꺼져 있을 가능성이 있다 (문서에 명시 없음).
- **접속:** Settings 탭 → 비콘 선택 → PIN `000000` (공장 기본값).
- **모드:** `ADD Beacon+` → iBeacon 슬롯 1개를 만든다. 출고 시 켜진 슬롯은 문서에 없으므로 직접 확인하고, Eddystone 등 다른 슬롯은 `Enabled`를 끈다. 패킷 혼선을 줄이기 위해서다.
- **UUID:** `504F5354-4943-0000-0000-000000000001`. 앞 6바이트는 "POSTIC"의 hex 값이다.
- **Major:** 행거 번호 (1 = HG-01, 2 = HG-02 …)
- **Minor:** 상품 번호 (101, 102, 103 …). 비콘마다 Major/Minor 조합이 겹치면 안 된다.
- **송출 간격:** 200ms. 기본값 1300ms는 인식 안정성 때문에 줄인다. 데이터시트 기준 0dBm에서 배터리는 약 147일이라 시연에는 무관하다.
- **TX:** 0dBm (기본값)
- **저장:** Done → Save를 누른 뒤 다시 접속해서 값이 들어갔는지 확인한다.
- **일괄 설정:** 앱의 "Batch Configuration" 기능으로 여러 개를 한 번에 설정할 수 있다. 5~10개면 하나씩 해도 개당 2~3분이면 된다.
- **라벨:** 비콘 뒷면에 Major/Minor를 적은 스티커를 붙인다.

### G1 설정
- 핫스팟(2.4GHz)에 연결한다.
- 업로드 방식: HTTP(S) POST, 주기 1초.
- UUID 필터나 RSSI 필터가 있으면 `504F5354-4943`만 통과시킨다.
- 상세 설정 절차와 페이로드 포맷은 조사 결과로 확정한다 (§10).

## 5. 데이터 흐름

```
BP106 ×N ──BLE adv──▶ G1 ──HTTP(S) POST JSON (1초)──▶ Supabase Edge Function `g1-ingest`
                                                          │ upsert
                                                          ▼
                                            tag_presence / sightings (Postgres)
                                                          │ Realtime
                                                          ▼
                                      React 웹 (Vercel) — 손님 화면 / 직원 대시보드
```

- **우선 경로:** G1이 Edge Function URL로 직접 POST한다. 인증 헤더 없이도 되게 `--no-verify-jwt`로 배포하고, 대신 URL 쿼리에 비밀 토큰(`?key=...`)을 붙여 검증한다.
- **대체 경로:** G1이 HTTPS를 못 쓰거나 헤더 문제로 막히면 노트북 Node 중계 `relay`를 쓴다. 경로는 G1 → `http://노트북IP:8080/g1` → supabase-js upsert. 중계는 같은 페이로드 파서를 재사용한다.
- **시연 보험:** `simulate` 스크립트가 등록된 태그들의 가짜 sighting을 1초마다 보낸다. 켜져 있으면 화면에 배지를 띄운다.

## 6. 인식 판정 규칙

- **온라인:** `now - last_seen ≤ 10초`. 값은 실측 후 조정한다.
- **신호 세기:** 최근 RSSI의 이동평균을 쓴다. 막대 아이콘 3단계로 보여준다.
- **행거 그룹:** Major로 묶는다. G1이 1대라 행거별 위치 구분은 Major 매핑으로 하고, RSSI는 거리감 표시용으로만 쓴다.
- **판정 위치:** 클라이언트에서 `last_seen`으로 판정하고 1초마다 다시 그린다. 서버 크론은 쓰지 않는다.

## 7. Supabase 스키마 (초안)

| 테이블 | 주요 컬럼 |
|---|---|
| `hangers` | `id` ('HG-01'), `name`, `zone` ('A-01'), `major` |
| `products` | `id`, `name`, `brand`, `price`, `color`, `material`, `image_url`, `sizes` (jsonb, 예: `{"S":2,"M":4,"L":1,"XL":0}`) |
| `tags` | `id` ('A7-32F1' 형식 표시용), `uuid`, `major`, `minor`, `product_id` → products, `hanger_id` → hangers |
| `tag_presence` | `tag_id` PK → tags, `last_seen`, `rssi`, `rssi_avg`, `gateway_mac` |
| `sightings` | `id`, `tag_id`, `rssi`, `gateway_mac`, `received_at` — 수신 로그 산출물용 |
| `orders` | `id`, `product_id`, `size`, `type` ('fitting' \| 'purchase'), `status` ('preparing' \| 'ready' \| 'done'), `pickup_code` ('B-43'), `amount`, `created_at` |

- **Realtime:** `tag_presence`, `orders`에 켠다.
- **권한(RLS):** 시연용 최소 수준이다.
  - anon은 전체 읽기만 가능하다.
  - `orders` insert와 `status` update는 anon에게 허용한다.
  - `tag_presence`와 `sightings` 쓰기는 Edge Function(service role)만 한다.
- **시드:** 상품 N개와 행거 2개. 이미지는 계획서 느낌의 옷 사진(무료 이미지나 직접 촬영)을 쓴다.

## 8. 화면

**손님 화면 `/`** (모바일 웹, 계획서 앱 시안 느낌)
1. **홈:** 인식된 행거 카드(`인식됨 · 3벌`)와 상품 썸네일. 실시간으로 갱신된다.
2. **행거 상세 "앞에 걸린 옷":** 상품 리스트, 신호 막대, `수신 게이트 GW-01`.
3. **상품 상세:** 이미지, 가격, 사이즈별 재고, 태그 ID, 소재, 피팅룸.
4. **피팅 요청 / 구매하기:**
   - 구매는 목 결제 시트로 간다. POSTIC Pay와 카드 선택 화면을 거쳐 1.5초 로딩 후 성공한다.
   - 피팅은 결제 없이 바로 요청한다.
5. **픽업 번호:** `B-43` 큰 숫자, 대기 팀 수, 결제 금액과 수단, 바코드 모양.

**직원 대시보드 `/admin`** (태블릿/노트북)
- **태그 상태 표:** `N/N 온라인`, 태그별 `last_seen`, RSSI, 온라인/오프라인 점.
- **수신 로그:** 최근 sighting 스트림. 계획서 산출물 "수신 로그"에 해당한다.
- **주문·피팅 요청 목록:** 상태 버튼(준비 중 → 픽업 대기 → 완료). 바꾸면 손님 화면에 실시간으로 반영된다.
- **시뮬레이터 토글:** 시연 보험용.

## 9. 스택

- **프론트:** Vite + React + TypeScript, Tailwind CSS, React Router, `@supabase/supabase-js`
- **백엔드:** Supabase (Postgres, Realtime, Edge Function / Deno)
- **배포:** Vercel (프론트), Supabase (함수)
- **대체 중계:** Node 20 + `express` (노트북)

## 10. 오늘 일정 (시간 박스)

하드웨어 위험을 가장 먼저 검증한다.

| 순서 | 할 일 | 목표 시간 |
|---|---|---|
| 1 | Supabase 프로젝트, 테이블, 시드, `g1-ingest` 배포 | 45분 |
| 2 | BP106 N개 설정 → G1 핫스팟 연결 → 업로드 URL 지정 → `tag_presence`에 N개 들어오는지 확인 | 60분 |
| 3 | React 손님 흐름 (홈 → 행거 → 상세 → 목 결제 → 픽업) | 2시간 |
| 4 | 직원 대시보드 + 시뮬레이터 | 1시간 |
| 5 | Vercel 배포, 통합 테스트, 시연 리허설 (태그 떼기/붙이기 시나리오) | 1시간 |

2단계에서 막히면 바로 대체 경로(노트북 중계)로 전환한다. 그래도 막히면 시뮬레이터로 3~5단계를 계속 진행하고, 하드웨어는 병행해서 디버깅한다.
