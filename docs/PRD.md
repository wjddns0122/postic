# POSTIC 프로토타입 PRD

- 버전: v0.1 (중간평가 시연용) · 작성일: 2026-10-27 · 담당: 노정운(CTO)
- 상태: 기능 동작 확인 완료(실장비 3/3 인식), UI 고도화 단계

## 1. 한 줄 요약

옷에 달린 BLE 태그를 매장 게이트가 자동으로 인식하고, 손님은 폰으로 "지금 앞에 걸린 옷"을 보고 바로 피팅 요청·결제·픽업까지 끝낸다.

> 오프라인 상품이 온라인으로 연결되는 리테일의 시작 — POSTIC (Battery-free Smart Inlay · Store Node · Retail OS)

## 2. 문제

| 대상 | 문제 |
|---|---|
| 손님 | 직원·재고 확인 대기, 선택→피팅→결제가 끊김, 같은 요청 반복 |
| 매장 | POS는 "구매"만 기록. 관심·피팅·이동 데이터는 상품 이동보다 늦게, 혹은 아예 안 남음 |

기존 대안의 한계: POS(계산대 종속) · RFID 계산대(고정형 인식) · 컴퓨터 비전(높은 구축비).

## 3. 이번 프로토타입의 목표 (사업계획서 "01 기술 검증")

1. **Tag ID → Gate → DB → App** 흐름을 실물로 증명한다.
2. 걸려 있는 상품이 **전부** 실시간 인식된다 (대시보드 N/N).
3. 손님 흐름을 끝까지 보여준다: 인식 → 상세 → 피팅/구매 → 목 결제 → 픽업 번호.
4. 직원 처리(픽업 준비 완료)가 손님 화면에 즉시 반영된다.

### 하지 않는 것 (Non-goals)
배터리리스 인레이, 실제 PG 결제, 정밀 위치(AoA/삼각측량), 로그인·회원, POS/ERP 연동, 다점포, 폰 BLE 직접 스캔.

## 4. 사용자와 핵심 시나리오

**손님 (모바일 웹, 심사위원 폰)**
1. 매장 입장 → 홈에서 "인식됨 · 3벌" 확인
2. 행거 HG-01 선택 → "앞에 걸린 옷" 목록(실시간, 신호 세기 표시)
3. 상품 선택 → 사이즈·재고·소재·태그 ID 확인
4. 피팅하기(피팅룸 FR-03 배정) 또는 구매하기 → 결제 시트(목) → 결제 승인
5. 픽업 번호 B-41 화면 → 직원이 준비 완료하면 "픽업 대기"로 실시간 변경

**직원 (태블릿/노트북 대시보드)**
1. 태그 온라인 현황 N/N, 태그별 RSSI·마지막 수신
2. 주문·피팅 요청 목록 → 상태 버튼(준비 중 → 픽업 대기 → 완료)
3. 인식 기준 조정(RSSI 임계값, 온라인 유지 시간), 게이트 원본 데이터 확인
4. 장비 장애 시 시뮬레이터(화면 전체에 "시뮬레이션" 배지)

## 5. 시스템 구성

```
FSC-BP106 ×3 (BLE 비콘, 상품당 1개)
   │ BLE 광고 (Eddystone TLM/URL, iBeacon)
   ▼
Minew G1 게이트웨이 (g1-e-grapes, Wi-Fi → 폰 핫스팟)
   │ HTTPS POST, JSON-PREPARSED, 1초 주기
   ▼
Supabase Edge Function `g1-ingest` ── MAC → 상품 매핑 → tag_presence upsert
   │ Realtime(WebSocket)
   ▼
React 웹 (Vercel): 손님 `/` · 직원 `/admin`
```

- 백업 게이트: 노트북 BLE 스캐너(`scanner/scanner.py`)가 같은 형식으로 업로드
- 인식 판정(클라이언트): `마지막 수신 ≤ 10초` AND `RSSI 이동평균 ≥ 임계값`
- 거리 표시: RSSI ≥ -65 dBm "바로 앞", 그 외 "근처"

### 데이터 (Supabase)
| 테이블 | 용도 |
|---|---|
| `products` | 상품(이름, 가격, 색상, 소재, 사이즈별 재고, 이미지, 행거·존, 태그 major/minor, 비콘 MAC) |
| `tag_presence` | 태그별 마지막 수신 시각·RSSI·게이트 (실시간) |
| `orders` | 구매/피팅 요청, 상태, 픽업 번호(B-41~), 결제 수단 |
| `settings` | RSSI 임계값, 온라인 유지 시간 (실시간 공유) |
| `gateway_raw` | 게이트 마지막 원본 페이로드, 수신 횟수 |

## 6. 화면 요구사항

### 손님 (모바일 375~430px 기준)
| 경로 | 화면 | 필수 요소 |
|---|---|---|
| `/` | 홈 | 인식 상태 필(인식됨 · N벌, 펄스), 프로모션 카드 캐러셀, 내 진행 상황(진행 중 주문 카드), 인식 행거 목록(행거별 감지 수·썸네일), 다시 스캔 |
| `/hanger/:id` | 앞에 걸린 옷 | 게이트·행거 배지, 신호 막대, 행거 일러스트(감지된 옷 강조), 갱신 시각, 인식된 상품 리스트(가격·사이즈 칩·바로 앞/근처), 감지 안 된 상품은 흐리게 |
| `/p/:id` | 상품 상세 | 큰 이미지+가격 배지, 사이즈 선택(재고/품절), 정보 표(태그 ID·소재·추정 위치·수신 게이트·피팅룸), 피팅하기/구매하기, 결제 바텀시트(수단 3종, 1.5초 승인 로딩, "시연용 가상 결제" 고지) |
| `/order/:id` | 픽업/피팅 번호 | 큰 번호(B-41), 상태(포장 준비 중/픽업 대기/수령 완료), 대기 팀 수, 상품·금액·수단·장소, 바코드, 완료 알림, 닫기 |

### 직원 (태블릿·노트북 1024px+)
| 경로 | 필수 요소 |
|---|---|
| `/admin` | KPI 4개(태그 온라인 N/N·처리 대기·오늘 주문·게이트 수신 횟수), 태그 상태 표(온라인 점·ID·상품·행거·Major/Minor·MAC·RSSI·마지막 수신·SIM 표시), 인식 기준(RSSI 슬라이더·유지 시간), 시뮬레이터(켜기/끄기·태그별 체크), 주문 목록(번호·구매/피팅·상품·금액·상태·다음 상태 버튼), G1 설정값(URL 복사), 마지막 게이트 원본 데이터 |

### 공통 규칙
- 모든 상태 변화는 새로고침 없이 실시간 반영
- 시뮬레이터 데이터가 화면에 있으면 손님·직원 화면 모두 "시뮬레이션" 배지 필수 (가짜를 진짜처럼 보이지 않게)
- 상품 이미지: `image_url`이 있으면 사진, 없으면 대체 표현
